# Portfolio design research

The redesign uses an editorial shell, evidence-led case studies, and a small number of diagrams whose scope and relationships are explicit. These patterns informed the design; no reference site's code, copy, or visual identity was copied.

- **Lead with operational credibility, then show the work.** Kevin Sloan's infrastructure portfolio establishes positioning before project case studies and diagrams. This supports a concise portfolio introduction followed by detailed project evidence. [Kevin Sloan — Infrastructure Portfolio](https://kevinsloan.net/)
- **Tell each project as a response to constraints.** Cloudflare's fleet-management engineering article describes the scaling problem, shortcomings of prior workflows, and the system built in response. Case studies can use the same challenge/constraints/decisions/evidence logic without implying unmeasured outcomes. [Cloudflare — Redefining fleet management](https://blog.cloudflare.com/redefining-fleet-management-at-cloudflare)
- **Pair technical narrative with focused supporting visuals.** Stripe's Connect engineering article presents a coherent story with specific implementation details and diagrams, rather than fragmenting every point into feature cards. [Stripe — Connect: Behind the front-end experience](https://stripe.com/blog/connect-front-end-experience)
- **Keep architecture diagrams scoped and legible.** Cloudflare distinguishes broad reference architectures from focused diagrams for a solution or use case. This informed the explicit caveat and evidence boundary around the portfolio's service map. [Cloudflare — Reference architecture: how to use](https://developers.cloudflare.com/reference-architecture/how-to-use/) · [Cloudflare — Diagram guidance](https://developers.cloudflare.com/reference-architecture/diagrams/)
- **Use nodes and edges to communicate real relationships.** Grafana's node-graph guidance treats nodes and edges as representations of infrastructure, dependencies, and hierarchies, with meaningful node/edge details and pan/zoom for larger graphs. The portfolio applies that grammar only to documented services and links. [Grafana — Node graph](https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/node-graph/)
- **Make interactivity reveal useful detail.** Stripe's Markdoc account describes composable interactive diagrams as a way to explore technical concepts. Here, selection reveals service purpose, decisions, and evidence/limits instead of decorative motion. [Stripe — How Stripe builds interactive docs with Markdoc](https://stripe.com/blog/markdoc)

## Resulting direction

Use a restrained editorial layout, clear narrative hierarchy, and a limited number of project-specific diagrams. Prefer verifiable engineering detail and accessible interaction over decorative topology or dashboard-like cards.
